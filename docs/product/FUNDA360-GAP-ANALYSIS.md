# Funda360 — Top-Tier Gap Analysis

Companion to [FUNDA360-CURRENT-STATE.md](FUNDA360-CURRENT-STATE.md). Priorities: **P0** critical foundation/security/correctness · **P1** required for a genuinely top-tier product · **P2** important enhancement · **P3** advanced/future.

| Domain | Current State | Target State | Gap | Priority |
|---|---|---|---|---|
| Audit logging | No audit trail beyond per-row created_by/updated_by | Queryable cross-domain audit log for sensitive actions (role changes, finance, medical, behaviour) | Build an `audit_log` table + write path (likely via triggers on the sensitive tables, or an explicit service call from the RPCs that already exist) | **P0** |
| Notifications | None | Email at minimum for finance/attendance/behaviour events; in-app inbox later | New domain from scratch: table, dispatch service, templates, preference model | P1 |
| MFA | None (email/password only) | TOTP MFA at least for finance/admin roles | Supabase Auth supports MFA natively — mostly a frontend enrolment/challenge flow + policy decision on who's required | **P0** for finance/admin roles once real money moves |
| Data retention / deletion (POPIA) | Soft-delete/deactivate only, no purge | Documented retention policy + a real deletion/anonymization path for a leaver who invokes their rights | Needs a product/legal decision first, then an engineering path — do not build a delete mechanism without that decision, per POPIA risk of getting it wrong either direction | **P0** (decision), P1 (implementation) |
| Consent management | None | Explicit consent capture for guardians (data processing, photo/media use, POPIA) | New table + UI; low complexity, currently entirely absent | P1 |
| Global search / command palette | None | Cross-entity search (learner/employee/guardian by name/number) | New capability, moderate scope | P2 |
| System configuration UI | None | School-level settings screen (already have `schools` row fields like timezone/currency/language unused by any settings UI) | Build the UI — the data model mostly already supports it | P2 |
| Learner bulk import/export | Export exists (CSV, Reports module); import does not | CSV import with validation + duplicate detection for onboarding a new school's roster | New feature; genuinely valuable for commercial onboarding | **P1** (blocks fast school onboarding) |

## Categorized summary (for the final audit report)

**PARTIAL** (meaningful functionality exists, real work remains): tenant switching UI, school onboarding, file storage breadth, learner documents (versioning/expiry), transfers, alumni handling, HR reporting depth, admissions pipeline UX, attendance reporting depth, attendance alerts (not persisted), behaviour intervention tracking, Parent Portal fees tab, Executive dashboard (hardcoded status row), component library depth, accessibility coverage.

**NEEDS HARDENING** (works, but not production-grade yet): Executive dashboard's hardcoded "Authentication: online" status row (actively misleading), accessibility color-contrast token (excluded from tests rather than fixed), Finance monetary math on the frontend (uses JS `number`, not a decimal library — low real-world risk at ZAR-cents scale but worth a documented decision, see Finance docs).

**MISSING** (no meaningful implementation): audit logging, notifications (all channels), MFA, data retention/deletion policy, consent management, global search, system config UI, learner bulk import, report cards/transcripts, lesson planning, homework-distinct-from-assessments, question banks/rubrics/moderation, timetable auto-gen/substitution/published-state/parent view (parent view now P1), staff attendance/leave, employee documents, Parent Portal messaging/documents/timetable, Learner Portal (deferred by design), payment gateway live integration (blocked on credentials), budgets/expenses/suppliers (deliberately deferred), bank reconciliation, all communication channels beyond auth email, mobile apps, school operations (inventory/library/transport/procurement/facilities), document versioning/e-signature, generic workflow engine (deliberately not recommended — build concrete workflows instead), AI/Funda Intelligence (deliberately deferred pending a provider decision), public API.

**BLOCKED**: live payment gateway integration — needs real merchant/provider credentials and a business decision (which gateway, whose merchant account) that cannot be made by this audit; POPIA "compliance" claims — needs legal review, not engineering judgment; AI features — needs an explicit LLM-provider/data-handling decision before any code.
