# Funda360 — Pilot Setup Checklist

For whoever is preparing a school for its Funda360 pilot. Work through this in order — later steps depend on earlier ones.

## Tenant & accounts

- [ ] **School/tenant created** — the school's profile exists in Funda360 (name, registration details, contact information under **Administration → School Profile**).
- [ ] **Principal account created** — via **Administration → Users & Roles → Add user**, role: Principal.
- [ ] **Teacher accounts created** — either via **Users & Roles** (role: Teacher) or, if the person already exists as an employee record, via that employee's profile → **Provision login**.
- [ ] **Roles verified** — sign in as each newly-created account (or ask them to) and confirm the sidebar/dashboard matches what that role should see.

## Academic structure

- [ ] **Academic year configured** — under **Academics → Academic Years**, with one marked active.
- [ ] **Terms configured** — under **Academics → Terms**, for the active academic year.
- [ ] **Grades configured** — under **Academics → Grades**.
- [ ] **Classes configured** — under **Academics → Classes**, each linked to a grade.
- [ ] **Subjects configured** — under **Academics → Subjects**, if the pilot will use the Assessments/gradebook feature.

## People

- [ ] **Learners loaded** — under **People → Learners**, either added individually or however your pilot's data-loading process works.
- [ ] **Learner-class enrollment configured** — each learner has a current enrollment record (grade, class, status) under their profile's **Enrollment** tab.
- [ ] **Employees loaded** — under **People → Employees**, for any staff who need a record (whether or not they get a login).
- [ ] **Teacher-class assignments configured** — under **Academics → Teaching Assignments**, so each teacher's Attendance page shows the right classes.

## Data readiness

- [ ] **Initial attendance data prepared, if required** — decide whether the pilot starts with a clean slate or backfills recent registers. If backfilling, confirm who's doing it and by when.

## Access & verification

- [ ] **Login credentials distributed securely** — not by unencrypted email or shared chat; use whatever secure channel your school/pilot policy requires.
- [ ] **Principal login tested** — someone has actually signed in as the principal account and reached the dashboard.
- [ ] **Teacher login tested** — same, for at least one teacher account, confirming they see only their own assigned class(es) under Attendance.
- [ ] **Tenant isolation verified** — if piloting more than one school, confirm a login from School A cannot see School B's data anywhere in the product.
- [ ] **Mobile access checked** — the app has been opened and used on an actual phone, not just resized on a desktop browser.

## People readiness

- [ ] **Pilot users briefed** — principal(s) and teacher(s) have seen the relevant Quick Start guide ([Principal](FUNDA360_PRINCIPAL_QUICK_START.md) / [Teacher](FUNDA360_TEACHER_QUICK_START.md)) and know how to report a problem ([Bug Report Template](FUNDA360_BUG_REPORT_TEMPLATE.md)) or give feedback ([Feedback Form](FUNDA360_PILOT_FEEDBACK_FORM.md)).

---

Once every box above is checked, the school is ready to begin using Funda360 for real.
